# Steam Workshop Uploader

It was primarily created to easily exclude files or folders from being uploaded.

You can use the `--glob` and `--ignore-file` options to specify files or folders to exclude (case-sensitive). By default, files and directories matching ignore patterns from files like `.ignore` and `.gitignore` are automatically excluded.

I resisted the urge to name it 'Yet Another Workshop Uploader'...

## Creating a Workshop Item

You can create a workshop item using the following command:

```shell
workshop create --content 'path/to/workshop/content/folder' --app-id 0 # App ID of the game
```

Currently, all arguments for the `create` command are optional, and you will be prompted interactively for any required inputs.

To disable prompts for scripting purposes, use the `--no-prompt` flag.

In the Mod Agent build, creation without `--preview` uses an embedded 1024 x 1024 green Mod Agent logo on solid black. No cover prompt is required. Supply `--preview /absolute/path/to/image.png` to use another cover. Updates without `--preview` preserve the published cover. To replace the cover later on the same item without uploading its content again:

```shell
workshop --no-prompt update --content '/path/to/content' --no-content-update --preview '/path/to/new-cover.png'
```

The editable copy of the default is `skills/steam-workshop/assets/default-cover.png`. The binary embeds that image at build time and keeps its temporary copy until the upload finishes. The asset is derived from the approved product mark; the pure-black 1024 x 1024 canvas adds no new artwork. `tools/generate_default_cover.cjs` can regenerate the asset from the product's `build/brand/module-mark.png` with an authoring-only Sharp installation. Rebuild the binary after changing the asset.

To see all available options, use the `--help` flag.

## Updating a Workshop Item

A file like the one below should be located in the root of the workshop item's content folder:

##### `workshop.toml`

```toml
app_id = 0              # App ID of the game
item_id = 0             # Workshop item ID
tags = ["mytag"]        # Item tags
language = "english"    # Item title and description language
```

This file is automatically generated when a workshop item is created using this tool. If you are trying to use the tool on an already created workshop item and don't want to create `workshop.toml` by hand, you can use `workshop init`:

```shell
workshop init --content 'path/to/workshop/content/folder' --app-id 0 --item-id 0
```

You can then update the item using the following command:

```shell
workshop update --content 'path/to/workshop/content/folder'
```

To inspect which files will be uploaded or excluded by ignore rules:

```shell
# List files that will be uploaded
workshop files 'path/to/workshop/content/folder'

# List ignored files and directories
workshop files --ignored 'path/to/workshop/content/folder'
```

To see all available options, use the `--help` flag.

## Portable Mac and Windows skill packages

The Mod Agent package includes one skill with `bin/macos-universal/workshop` and `bin/windows-x64/workshop.exe`. Keep each binary beside its matching Steam library. Players need the running, signed-in Steam client and publishing permissions, not a Rust/Python installation or SteamCMD login. Windows x64 uses a static C runtime to avoid a separate VC++ runtime prerequisite.

Build Windows natively with `cargo build --locked --release --target x86_64-pc-windows-msvc`. The repository's `.cargo/config.toml` supplies the static CRT setting. On macOS/Linux, `cargo-xwin 0.23.1` can cross-build the same target; a cross-build is not a Windows runtime test.

For a Windows-only package, use `tools/package_skill.py --platform windows-x64 --binary <workshop.exe> --steam-library <steam_api64.dll> --output <NEW_DIRECTORY>`. To produce one combined package, start with the Mac artifacts and add `--additional-runtime windows-x64 <workshop.exe> <steam_api64.dll>`. Every native payload, default cover, and corresponding source is included in the SHA-256 manifest. Temporary build caches and OS metadata are excluded.

Run `python tools/smoke_skill.py <EXTRACTED_SKILL> --platform windows-x64` on a Windows x64 host. The check loads the shipped EXE/DLL, verifies the default-cover and custom-cover paths, and stops at local validation before Steam initialization. It needs no Steam login. `--static` checks hashes, PE architecture and imports without execution. The native skill-package workflow runs the source tests, packager tests, and this local smoke gate before uploading its artifact. Actual Steam upload/update still needs a signed-in Steam session and a separate live test.

## Settings

The config file is located at `$XDG_CONFIG_HOME/io.github.nozwock.steam-workshop-uploader/config.toml`. Or, you can place `config.toml` next to the executable, which will take priority.

You can set a default language for title and description or disable the automatic opening of the workshop item page after creating or updating an item in the config file.

Support for predefined tags is available for workshop items based on the App ID, defined in the config file:

```toml
[valid_tags]
# App ID = List of Tags
0000 = ["overhaul", "skins", "map", "etc"]
0001 = ["mod"]
```
